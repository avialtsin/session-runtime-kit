# session-artifacts — табло сессии

Пользователь не листает чат, чтобы понять, что происходит. Он смотрит на строку внизу вкладки:
что делается сейчас, что открыть, что дальше. А потом по табло разбирает все сессии: что и зачем
делали, что он просил и показывал, что решили.

## Коротко

- Первое сообщение с задачей — сразу, ещё на разборе, `artifacts init "<тема>"`: папка
  `sessions/NNN-…/` и табло `artifacts.md` в ней. Табло коммитится вместе с работой.
- Табло пишется само: просьбы и кадры пользователя, коммиты, задачи доски, каждый кадр, который ты
  посмотрел, и что ты делаешь сейчас. Для этого ничего делать не нужно.
- От тебя две вещи. Крупная смена этапа — `stage "<коротко>"`; код готов — `stage "Основное готово —
  проверяю"`, и проверка дальше без остановки. Закончил — `stage "Готово: <итог языком продукта>"`.
- Описание команды (`description`) — по-русски, языком дела: его видно в строке внизу и под кадрами
  в галерее.
- По желанию, когда есть что сказать: `link <url|файл> "<что это>"` — что показываешь (страницы
  `orca tab create`/`goto` и файлы `orca file open` попадают сами); `next`, `decision`, `problem`,
  `queue`, `done`, `now TASK-N`, `why`.
- Ответ пользователю — сразу с сути. «Записал на табло», «табло завёл» в чат не писать: табло видно
  в строке внизу.
- Всё остальное — `~/.agents/skills/session-artifacts/SKILL.md`, команды — `artifacts help`.

## Что видит пользователь

Строка внизу вкладки Claude, до четырёх строк, пустые не пишутся; ссылки — Cmd+клик:

```
▶ Основное готово — проверяю · 19:40 · ⋯ 19:52 Снимаю кадры телефона
👁 shop.localhost:5173 · черновик письма
→ Дальше: кадры телефона, потом коммит
🖼 Кадры 12 · ⚠ 1 · Очередь 1
```

- `▶` — этап и время, когда он сменился; за ним — что идёт на самом деле, само: `⋯` описание
  команды, которую агент выполняет (английское — просто «работает»), `✓ … ждёт ответа` и начало его
  ответа в конце хода, `⟳` сводка Claude Code после простоя. Пока после этапа ничего не было —
  задача или тема сессии.
- `👁` — что смотреть, новое первым: стенд, файл, страница. Только живые: стенд на этой машине
  отвечает, файл на месте.
- `🖼 Кадры` — галерея вкладки; `⚠` — открытые находки; очередь. Табло в строке нет: его читают
  агент и разбор сессий.

Строка перечитывает табло раз в 5 секунд и меняется только вместе с ним.

## Табло

Простой markdown: его дёшево читать и править, он открывается где угодно. Сверху — только нужное
сейчас, ниже — история по этапам. Пустые разделы не пишутся, картинок в табло нет — только ссылки.

```markdown
# Виды «Список» и «Лента»

Сессия 186 · начата 07.10.2026 14:02 · 📎 2 ваших кадра · ● 3 коммита

- **Сейчас:** Основное готово — проверяю · 19:40
- **Задача:** TASK-3061 Список и лента
- **Смотреть:** [стенд магазина](http://shop.localhost:5173) · [черновик](../../docs/x.md)
- **Дальше:** кадры телефона, потом коммит

**Зачем.** Риелтору нужно пролистать объекты подряд, а таблица режет карточки.

## Итог
## Решения
## Находки
## Очередь
## Заведено за сессию
## Ход сессии

### 19:40 · Основное готово — проверяю

- **19:41** 🗣 Карточки слишком высокие — [📎 кадр](shots/1941-user-1.png)
- **19:44** ⚠ На телефоне лента уходит вправо — [кадр](shots/19-44-10_лента.png)

### 18:20 · Делаю ленту

- **18:31** ● коммит 1a2b3c4 core: feed view (core/feed)
```

- «Итог», «Решения» — языком продукта: что изменилось для пользователя и почему так. «Итог» —
  3–6 строк, а не список каждого шага.
- «Ход сессии» — по этапам, новые сверху. Каждый `stage` открывает новый этап; под ним по времени
  просьбы пользователя (🗣 — начало его текста, с его кадрами ссылкой «📎 кадр»), сводки Claude Code
  после простоя (⟳), коммиты (●), задачи на доску (＋), решения на доску (⚖), материалы на доску (📄),
  главные кадры (★), находки (⚠ / ✓).
- Табло можно править и руками: скрипт читает его обратно и сохраняет чужие разделы.
- Табло прежнего вида скрипт переводит в новый при первой записи.

Где лежит: `sessions/NNN-ДДММГГ_Тема/artifacts.md` в рабочем дереве вкладки. Номер — следующий
после последней сессии во всех деревьях проекта. В git-проекте без `sessions/` папка заводится
сама; вне git табло временное, в `.artifacts/` (не в git). Что такое сессия и что в её папке — общие
правила, раздел «Сессии».

## Кадры пользователя

Пользователь вставил кадр в чат и что-то о нём сказал — это сохраняется само, без агента:

- Claude Code кладёт каждую вставку в свою временную папку сессии (`images/<N>.png`, N — номер
  «[Image #N]» в сообщении). Хук сообщения сразу копирует кадр в `shots/` папки сессии
  (`1917-user-1.png`) и в галерею, а в «Ход сессии» пишет начало текста пользователя со ссылкой
  «📎 кадр» — в его время и в его этап. Так и для сообщений, отправленных посреди хода.
- Кадра в папке не оказалось — в конце хода хук достаёт его из истории чата и дописывает к той же
  записи. Табло ещё не заведено — просьбы и кадры ждут и переносятся при `init`.
- Кадр файлом, а не из чата, — `ask "…" --shot <файл>`.
- Замечание стало задачей — в карточку на доске ссылка на этот кадр (`sessions/NNN-…/shots/…`). Кадр
  остаётся в сессии, даже если задачу потом закроют.

## Кадры агента и галерея

- Каждый кадр, который агент посмотрел (Read картинки) или открыл пользователю (`orca file open`),
  хук сам кладёт в галерею вкладки — в фоне, агента не задерживает. Повторы отсекаются по
  содержимому файла. Подпись — имя файла и описание команды, которую агент выполнял перед этим.
- Галерея своя у каждой вкладки и лежит в главной копии репозитория,
  `.artifacts/gallery/<сессия>/` (не в git): удаление рабочего дерева после go-final её не трогает.
  Галереи, заведённые внутри дерева, переезжают туда сами.
- Галерея — все кадры по времени одним списком «картинка — текст», новые сверху, этапы — тонкими
  заголовками. Кадры пользователя — в том же списке, в синей рамке,
  с его словами; находки — в красной. Клик — во весь экран: масштаб колёсиком и щипком, двойной клик —
  1:1, ← → — листать.
- Кадр в git, рядом с табло, — только по слову агента: `shot <файл> "<подпись>" --key` (копия в
  `shots/` и ссылка в «Ходе сессии») или находка `problem "<что>" <файл>`.

## Что делается само (хуки Claude Code)

- Начало сессии — агент получает «Коротко» из этого файла и путь к табло. Заодно хук убирает из
  настроек Claude медленный хук repowise после каждого вызова инструмента (~0,4 с на вызов, по делу
  почти ничего): `repowise init` ставит его обратно. Хук repowise в начале сессии и его MCP остаются.
- Сжатие контекста (в том числе автоматическое) — вместо handoff агент получает верх табло: тему,
  задачу, «Сейчас», «Дальше», «Зачем», этапы, решения, открытые находки, очередь и последние 5
  просьб пользователя с путями к его кадрам. Агенту для этого ничего делать не нужно.
- Сообщение пользователя — его просьба и кадры в «Ход сессии» и галерею; сводка Claude Code, если
  была, — перед ней. Сообщения других вкладок, отчёты фоновых задач и автопродолжение после лимита —
  не просьбы, их табло пропускает.
- Перед командой (в фоне) — её описание в строку внизу: что агент делает сейчас.
- После команд — новые задачи доски в «Ход сессии»; решение доски (`go-board decision`,
  `backlog decision create`) — с номером в «Решения» и «Ход сессии»; материал, выложенный
  `go-board publish`, — в «Ход сессии»; `orca file open <файл>` — файл в «Смотреть»,
  `orca tab create --url` и `orca goto --url` — страница (одна на адрес стенда). Коммит — в «Ход
  сессии» при следующей записи табло (сообщение пользователя, `stage`), а не сразу: иначе дерево
  после коммита снова грязное и `git switch` / `rebase` отказываются.
- После Read картинки — кадр в галерею.
- Конец хода — начало ответа агента в строку внизу, недостающие кадры пользователя — из истории
  чата. Ход останавливается только если табло не заведено — раз на сообщение.

## Связь с доской и проектом

- Смысл задачи — в её карточке на доске; на табло — коротко в «Зачем».
- Мелкое решение — `artifacts decision`; значимое — решением на доску (скилл `go-board`), на табло оно
  попадёт само.
- Задача закончена — итог и ссылки на главные кадры ещё и в карточку.
- Что идёт в «Смотреть» в конкретном проекте (стенды, порты) — в `AGENTS.md` проекта, раздел
  «Артефакты сессии».
- Воркер-гость (скилл `go-work`) заводит своё табло; коммитит его хозяин дерева.

## Codex

Хуки табло пока стоят только у Claude Code; в Codex табло ведётся теми же командами, сам, включая
`ask` для просьб пользователя.

## Где это живёт и как улучшать

Скилл — часть репозитория `session-runtime` (папка, куда его склонировали): скрипт `artifacts`,
`statusline.sh`, этот файл, глобальные правила, установка. Править только там; на машину ставит
`install.py` (см. README репозитория).
