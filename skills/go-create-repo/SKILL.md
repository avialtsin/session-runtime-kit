# go-create-repo — новое пространство проекта

Скилл заводит то, что нужно каждому проекту, и не таскает в репозиторий содержимое глобальных
инструментов: программа `backlog` и скилл `agent-context-pipeline` стоят на машине один раз, в проект
попадают только их данные и короткие ссылки в `AGENTS.md`.

## Что получает проект

```
<проект>/
  AGENTS.md              ← инструкции: что за проект, доска, сессии, контекст кода, границы
  CLAUDE.md              → AGENTS.md
  README.md
  .gitignore             ← node_modules, .env, .repowise/, .context/packs/, .artifacts/
  package.json           ← только в новой папке: скрипты backlog, backlog:board, backlog:browser
  backlog.config.yml     ← доска Backlog.md
  backlog/
    completed/task-1000 - Поколение-1-начало-нумерации.md   ← якорь: задачи идут с TASK-1001
  sessions/              ← NNN-ДДММГГ_Краткое-описание/
  .context/checkpoints/  ← принятые контрольные точки agent-context-pipeline (коммитятся)
```

Шаблоны — `templates/AGENTS.md` и `templates/README.md`. Генератор — `scripts/scaffold.py`.
Пути — от папки скилла `~/.agents/skills/go-create-repo/`.

## 1. Собрать сведения

Нужно:

- **папка** — абсолютный путь. Если пользователь назвал только имя, а родительская папка не очевидна
  (обычно рядом с другими его проектами), — спросить;
- **имя** репозитория — латиница, по умолчанию имя папки;
- **описание** — одна строка по-русски: что это;
- **цель** — главный результат проекта;
- **GitHub** — создавать ли приватный репозиторий `<аккаунт>/<имя>` (аккаунт — `gh api user -q .login`);
- **Orca** — подключать ли проект в Orca.

Спрашивать только то, чего нельзя понять из разговора. Описание и цель для существующего проекта с
`AGENTS.md` не нужны.

## 2. Проверить машину

```bash
git --version; python3 --version; backlog --version; repowise --version
```

- Нет `backlog` — предложить поставить один раз на машину: `bun add -g backlog.md` или
  `npm i -g backlog.md`. Без согласия не
  ставить.
- Нет `repowise` — проект заводится и без него; сказать, что `agent-context-pipeline` заработает после
  `uv tool install "repowise==0.36.0"`. Без согласия не ставить.

## 3. Запустить генератор

Папка не пустая — сначала прогон без записи, показать пользователю отчёт:

```bash
python3 ~/.agents/skills/go-create-repo/scripts/scaffold.py --target <папка> --dry-run [остальные флаги]
```

Затем настоящий запуск:

```bash
python3 ~/.agents/skills/go-create-repo/scripts/scaffold.py \
  --target <абсолютный путь> \
  --name <имя> \
  --description "<что это>" \
  --purpose "<главный результат>" \
  [--update] [--adopt-claude-md] [--no-git]
```

Генератор печатает JSON-отчёт: по каждому пути — `created`, `exists`, `linked`, `appended`,
`adopted`, `skipped`, `incomplete` или `conflict`. Код выхода 1 — есть `conflict`.

- **Новые** файлы, папки и симлинки создаются всегда. Существующие не перезаписываются.
- **`--update`** — дописать недостающее в существующие файлы: разделы `AGENTS.md` (по заголовкам
  `## …`), строки `.repowise/`, `.context/packs/` и `.artifacts/` в `.gitignore`, скрипты в
  `package.json`. Только после согласия пользователя на то, что показал `--dry-run` (`incomplete`).
- **`--adopt-claude-md`** — в проекте обычный `CLAUDE.md` без `AGENTS.md`: переименовать его в
  `AGENTS.md` и поставить симлинк. Только с согласия пользователя.
- **Оба файла обычные** (`CLAUDE.md` и `AGENTS.md`) — генератор их не трогает. Предложить пользователю
  слить содержимое в `AGENTS.md` и заменить `CLAUDE.md` симлинком.
- Папка внутри другого репозитория — свой git не заводится; доска работает на git родителя.

Доска заводится через `backlog init` без мастера, с нашим конфигом: `backlog.config.yml` в
корне, статусы To Do / In Progress / Done, без проверки веток, без файлов инструкций и субагента от
Backlog.md. Правило работы с доской уже записано в `AGENTS.md`. Индекс repowise генератор не строит:
его построит первый запуск `agent-context-pipeline`.

Новая доска сразу получает **поколения задач**: генератор кладёт якорь
`backlog/completed/task-1000 - Поколение-1-начало-нумерации.md`, и CLI нумерует задачи с `TASK-1001`.
Последние три цифры — задача, всё перед ними — поколение. Ключа номера у `backlog task create` нет,
следующий номер — наибольший в `tasks/` и `completed/` плюс один, поэтому якорь — файл, а не команда.
Правило записано в разделе «Доска задач» шаблона `AGENTS.md`. Следующие поколения открывает скилл
`go-grooming`. Существующую доску генератор не трогает: поколения на ней откроет первый груминг.

## 4. Проверить

```bash
cd <папка>
backlog task list --plain        # доска отвечает (пустая — это нормально)
backlog task view TASK-1000 --plain   # якорь поколения 1 читается
readlink CLAUDE.md               # AGENTS.md
git status --short
```

Пробную задачу на доске не создавать.

## 5. GitHub — только с явного «да»

Это публикация во внешний сервис, согласие спрашивать каждый раз.

```bash
gh repo view "$(gh api user -q .login)/<имя>" >/dev/null 2>&1 && echo "ИМЯ ЗАНЯТО"
git add -A && git commit -m "chore: init workspace"
gh repo create <имя> --private --source=. --push
```

Имя занято — не перезаписывать, спросить другое. Коммит без GitHub — только если пользователь просил.

## 6. Orca — по желанию

Подключать через скилл `orca-cli`: прочитать его актуальное руководство и добавить проект по
абсолютному пути. Команды Orca не угадывать. Сразу после добавления — база рабочих деревьев от
локального `main`: `orca repo set-base-ref --repo path:<путь> --ref main --json` (по умолчанию Orca
берёт `origin/main`, и деревья создаются без незапушенных коммитов).

## 7. Отчёт

Коротко по-русски: путь, что создано, что уже было, что дописано, конфликты и что с ними делать, git
(ветка, коммит, GitHub-ссылка, если создан), Orca. В конце — как открыть доску: `backlog browser`.
