# go-work — запустить работу вкладками

Этапы: **go-mind** (понять) → **go-work** (сделать) → **go-final** (завершить) → пользователь тыкает
сборку → следующий этап.

Каждый агент — видимая вкладка Orca: пользователь может зайти в любую, посмотреть и поправить. Его
слово во вкладке главнее проджекта.

## 1. Понять работу

- **Вход** — замысел из `go-mind` или то, что обсудили сейчас: что делаем, зачем, что значит «готово».
  Чего-то нет — один короткий вопрос; задача совсем сырая — предложи `/go-mind`.
- **Что уже идёт** — `git status`, `orca terminal list`: чужие вкладки, деревья и несохранённые
  правки не задевать.
- **Разрежь на куски.** Что можно делать одновременно, какие файлы общие, что кого ждёт. Задачи на
  одни файлы — одному агенту подряд, а не двум сразу. Узкое место, которое ждут другие, — начать
  раньше всех.

## 2. Раскладка — одним сообщением

| раскладка | когда |
|---|---|
| сам, без вкладок | мелочь: правка в одном-двух местах с одной проверкой, или одна нить, которую не разделить |
| одна вкладка | одна отдельная работа: ресёрч, ревью, фича. Проджект не нужен: координатор — пользователь или эта сессия |
| проджект + воркеры в одном дереве | части одной вещи, изменения соседей должны быть видны сразу (сцена, сайт, экран) |
| проджект + воркеры в своих деревьях | независимые части без общих файлов |
| смешанно | например, 4 агента в 2 деревьях: части одной вещи вместе, независимое отдельно |

Воркеров 2–4. Где работает вкладка:

| работа | дерево |
|---|---|
| ресёрч, разбор, ревью — код не меняет | гостем в текущем дереве |
| часть одной вещи с соседями | общее дерево этапа — текущее или другое существующее |
| независимая часть, проба, которая может не войти | новое дерево от `main` или ветки этапа |

В сообщении пользователю:
- куски → роль → дерево и ветка → что сдаёт;
- куда сливаем в `go-final`: `main` или ветка этапа — по правилам проекта;
- что пользователь откроет в конце этапа и куда нажмёт.

После «да» — запуск. Дальше задачи воркеров внутри раскладки заново не согласуются. Новое
согласование — когда меняется смысл, объём или раскладка.

## 3. Запуск

**Файл этапа** — `этап_vN.md` в папке сессии: ссылка на замысел, раскладка, куда сливаем, таблица
«вкладка — роль — дерево — задача — статус» (её ведёт проджект). По нему `go-final` найдёт всё, что
надо закрыть.

**Задания** — файлами `/tmp/tabs/<этап>/<имя>.md`, по-русски: так кириллица и кавычки доходят как есть.
Шаблоны — в разделе 4.

**Новое дерево** (если нужно):

```bash
orca worktree create --repo path:<корень проекта> --name <имя> --base-branch <main|ветка этапа> \
  --no-parent --comment "<что делаем и что увидит пользователь — 1–3 строки>" --json
```

- Ветку Orca называет `<gitUsername>/<имя>`; у проекта своё правило — переименуй сразу:
  `git -C <путь дерева> branch -m <старое> <новое>`.
- Дерево собирается из коммита: нужна незакоммиченная работа — сначала коммит в свою ветку и
  `--base-branch` на неё.
- Файлы вне git (`.env`) скопируй сразу: путь дерева — часть `worktree.id` после `::`.
- `runtime_unavailable` — дерево часто всё равно создано: проверь `orca worktree list`, прежде чем
  повторять.

**Вкладка в дереве** — текущем или любом существующем:

```bash
orca terminal create --worktree path:<путь дерева> --title "<этап>: <роль>" \
  --command 'claude --dangerously-skip-permissions "$(cat /tmp/tabs/<этап>/<имя>.md)"' --json
```

Codex: `--command 'codex --dangerously-bypass-approvals-and-sandbox "$(cat …)"'`. До вкладок Codex
`SendMessage` не доходит: им пишут `orca terminal send --terminal <handle> --text "…" --enter`.

**Ты сам в Codex** (или у пользователя нет Claude Code): `SendMessage` и `ListAgents` у тебя нет.
Вкладки запускай как `codex …`, всем пиши через `orca terminal send`. Свой адрес для ответов —
`echo $ORCA_TERMINAL_HANDLE`: его вписывай в задания вместо имени сессии (`{PROJECT}` и
`{PROJECT_HANDLE}` — одно и то же).

**Проджект и воркеры.** Ты запускаешь только вкладку проджекта, в дереве этапа. Задания воркеров
готовы заранее, а запускает их проджект первым делом: он знает своё имя для `SendMessage` и
вписывает его в задания.

**Одна вкладка.** Запусти её сразу. Координатор по умолчанию — пользователь: вкладка говорит с ним в
своём чате. Координатор — эта сессия, если так решили: впиши в задание своё имя из `ListAgents`
(строка «This session is <имя>»).

**Пользователю** — одной строкой: какие вкладки, где, что он увидит первым. Дальше работа идёт во
вкладках, эта сессия свободна.

## 4. Задания

Вкладка ничего не знает о вашем разговоре: всё нужное — в первом сообщении. Пример живого задания —
`references/brief-example.md` (смысл, а не форма).

**Проджекту:**

```text
Ты — проджект этапа «<этап>» проекта <проект> (<путь>). Правила — ~/.agents/skills/go-work/project.md.
Замысел: <путь к замысел_vN.md или пять строк: что, зачем, готово, эталон, границы>.
Файл этапа: <путь к этап_vN.md> — раскладка, куда сливаем, таблица вкладок (ведёшь ты).
Воркеры: <имя> — <роль> — <дерево> — задание /tmp/tabs/<этап>/<имя>.md; … Запусти их первым делом.
Пользователь ждёт в конце: <что откроет и куда нажмёт>.
Чего не делать: <границы проекта: прод, пуш, чужое>.
```

**Воркеру** (`{PROJECT}` и `{PROJECT_HANDLE}` подставит проджект):

```text
Ты — <роль> в этапе «<этап>» проекта <проект>. Правила — ~/.agents/skills/go-work/worker.md.
Задача: <что сделать>. Зачем: <смысл одной строкой>. Эталон: <путь или пример>.
Готово: <как выглядит результат>; доказательство — <кадр / ссылка и куда нажать / замер>.
Результат пиши в <файл> по ходу.
Дальше по очереди: <следующие задачи, если есть>.
Где: <путь дерева, ветка>; <гость / общее дерево: твои пути — …, замок — … / своё дерево>.
Что уже известно: <факты из кода, решения пользователя, файлы>.
Проджект — сессия {PROJECT} (SendMessage); Codex пишет ему: orca terminal send --terminal {PROJECT_HANDLE} --text "<роль>: …" --enter.
Чего не делать: <границы>. Слово пользователя в твоём чате главнее проджекта.
```

## Подводные камни

- Задачи на доске создаёт только тот, кто в основной папке проекта: в разных деревьях CLI выдаст
  одинаковые номера.
- Номер папки сессии сверь с соседними деревьями: вкладки берут номера одновременно.
- У каждой вкладки свой порт dev-сервера.
- В zsh не называй переменную `path`.
- Заметку дерева меняй только по id: `orca worktree set --worktree "id:<repoId>::<путь>" --comment …`.
- Вкладка стоит на ручном «Allow» — сторож в фоне: `scripts/watch-prompts.sh <часть пути дерева>`.
  Своё дерево или временная папка — `orca terminal send --terminal <handle> --text 1`; прод, пуш,
  чужое, необратимое — `--text 3` и объясни вкладке.
