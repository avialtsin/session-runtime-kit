# go-doctor-repo — проверка репозитория и правки по согласию

Проекты заводятся скиллом `go-create-repo`, но со временем отходят от правил: проект добавили в Orca
вручную, `CLAUDE.md` стал обычным файлом, `.env` попал в git, правило о поколениях задач не
дописали. Доктор смотрит на **текущий репозиторий** (корень — `git rev-parse --show-toplevel`),
находит такие расхождения и чинит их — но только то, на что согласился пользователь.

Правила, с которыми сверяться, — глобальные (`~/.agents/AGENTS.md`) и скилл `go-create-repo`: что
должно быть в проекте и почему. Если в проекте сознательно сделано иначе и это записано в его
`AGENTS.md` — это не поломка.

## Думай вместе с пользователем

Доктор не решает за пользователя. Что-то выглядит странно, но может быть сделано намеренно, —
спроси. Правку можно сделать по-разному — покажи варианты с рекомендацией. Лучше один лишний
вопрос, чем «починенный» проект, который сломал чей-то замысел.

## 1. Осмотр — только чтение

До согласия ничего не меняй: ни файлов, ни настроек Orca, ни git. Что смотреть и зачем:

- **Устройство пространства.** `python3 ~/.agents/skills/go-create-repo/scripts/scaffold.py --target
  <корень> --dry-run --update` — генератор `go-create-repo` без записи покажет, чего не хватает
  (`incomplete`, `created`) и где конфликт. Отдельно: `CLAUDE.md` должен быть симлинком на
  `AGENTS.md` (`readlink CLAUDE.md`) — иначе Claude и Codex читают разные инструкции.
- **Доска.** `backlog task list --plain` отвечает. Есть якорь поколения
  (`backlog/completed/task-N000 - …`) и правило поколений в `AGENTS.md` — без них номера задач
  путаются после груминга. Нет второго трекера (TODO-файлы, списки задач в README, другая доска):
  трекер у нас один — Backlog.md.
- **Материалы и решения** (скилл `go-board`). В `AGENTS.md` есть абзац «Материалы и решения». Решения
  не пустые (`backlog decision list --plain`, затем файлы `backlog/decisions/`), у заменённых —
  статус `superseded` и строка «Заменено». Нет второй базы знаний рядом с доской (`second-brain/`,
  `wiki/`, `base/`): их перенос на доску — на груминге. Описание кода в `docs/` — норма.
- **Лишнее в репозитории.** Копии глобальных скиллов внутри проекта (например,
  `agent-context-pipeline` в `.claude/skills/`), `backlog.md` в зависимостях проекта. Глобальные
  инструменты стоят на машине один раз; копия в проекте устаревает и расходится с оригиналом.
- **Секреты.** `.env`, ключи и токены не должны лежать в git
  (`git ls-files | grep -iE '(^|/)\.env|\.pem$|id_rsa|ssh-keys'`, кроме `.example`/`.template`), а
  `.env` — быть в `.gitignore`. Секрет в git остаётся в истории и после удаления файла.
- **Git и GitHub.** Ветка `main`, есть приватный репозиторий `<аккаунт>/<имя>` (`gh api user -q .login`,
  `git remote -v`, `gh repo view --json visibility`), сколько коммитов не запушено — для сведения.
- **Артефакты сессии.** В `AGENTS.md` есть раздел «Артефакты сессии», а `.artifacts/` в `.gitignore`
  проекта — оба пункта покажет тот же `scaffold.py --dry-run --update`. Без раздела агенты не знают,
  как табло связано с `sessions/`; без строки в `.gitignore` файлы артефактов попадут в git на машине
  без глобального ignore. Строка внизу вкладки, хуки табло и сами скиллы ставятся на машину, а не в
  проект: `python3 <папка session-runtime>/install.py --dry-run` покажет, всё ли на месте (папку
  выдаст `readlink ~/.agents/skills/session-artifacts`).
- **Orca.** Проект подключён (`orca worktree current --json`), база рабочих деревьев —
  локальный `main` (`orca repo show --repo id:<repoId> --json`, поле `worktreeBaseRef`). Иначе
  рабочие деревья создаются от `origin/main` — без незапушенных коммитов.

Чего доктор не касается: порядок и содержание задач на доске, мёртвый код, старые ветки и
брошенные рабочие деревья — это `go-grooming`. Увидел такое — упомяни и предложи груминг.

## 2. Отчёт и согласование

Одним сообщением, коротко: что в порядке (одной строкой), что не так — и что предлагаешь. Удобно
разделить:

- **поправлю сам после «да»** — недостающие файлы и разделы (в том числе «Артефакты сессии»),
  симлинк, строки `.gitignore`, база Orca, лишние копии скиллов;
- **нужно ваше решение** — то, что публикует, удаляет или меняет чужой замысел: создать репозиторий
  на GitHub, убрать секрет из git (и сменить сам ключ — он уже утёк в историю), слить два файла
  инструкций в один, подключить проект в Orca;
- **не моё** — что отдать `go-grooming` или оставить как есть.

Жди ответа. Пользователь может согласиться на часть — делай только её.

## 3. Правки

Только согласованное и теми же средствами, что у `go-create-repo`:

- недостающее — `scaffold.py` (`--update` дописывает разделы `AGENTS.md` и строки `.gitignore`,
  `--adopt-claude-md` превращает обычный `CLAUDE.md` в `AGENTS.md` с симлинком);
- правило поколений — текст из раздела 6 скилла `go-grooming`; якорь на существующей доске кладёт
  груминг (`generation.py open`), не доктор;
- база Orca — `orca repo set-base-ref --repo id:<repoId> --ref main --json`;
- секрет — `git rm --cached` и строка в `.gitignore`; ключ сменить — за пользователем;
- GitHub — как в `go-create-repo`, только с явным «да»: это публикация.

Коммитить — по правилам проекта и с согласия пользователя; не пушить без его слова.

## 4. Перепроверка

Повтори осмотр по тем пунктам, что правил, и коротко скажи: что исправлено, что осталось и почему
(отказался пользователь, нужно его действие, передано в груминг).
